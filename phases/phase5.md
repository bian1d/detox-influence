Phase 5 — 换模型验证:A2 失效是 PPO 的锅,还是方法的锅?
OLMo-2-1B on the A2 / influence-function error budget

写给云端 agent 的说明:这是 Phase 4 的续集。Phase 4 在 GPT-Neo-125M 上把 RL-KL
影响函数锤死了(温度计 4 到 34,远超 0.3,A2 假设彻底失效)。Phase 5 换到 OLMo-2-1B
上,回答一个更根本的问题:那个失败是 PPO 这种训练范式特有的(到不了最优点),还是
这套影响函数方法本身的死穴?

本 spec 全程不用数学符号,用文字描述,避免渲染乱码。约定:
- theta-star = 被分析的那个模型快照(待定,见下)
- phi = 受分析的参数子空间(只取 MLP,不碰 attention 的 QKVO,跟 GPT-Neo 一致)
- beta = KL 系数
- Delta = A2 失效时留在曲率里的污染项(Phase 4 的核心量)
- 温度计 = (Delta 乘 p 的长度) 除以 (评估方向的长度),其中 p = inverse-F 乘 评估方向
- inverse-F = Fisher 矩阵的逆
- ICC = 组内相关系数,衡量有效奖励在同一 prompt 内不同回答之间的方差占比

先读 repo 根目录的 CLAUDE.md 和 CONTEXT.md,以及 reports/phase4_gptneo_negative_result.md
(GPT-Neo 的锤死备忘录,这是 Phase 5 的对照基线)。Phase 5 复用 Phase 4 验证过的
全部代码:src/phase4/ 里的 estimator(split-half、U-statistic、Delta-VP、HVP、MINRES)
原样搬过来,只改"模型加载"和"评估方向构建"两处。

==========================================================================
第 1 节:MLP 结构的关键差异(OLMo-2 跟 GPT-Neo 不一样,务必先搞清)
==========================================================================

GPT-Neo 的 MLP 是普通两层:c_fc(升维)然后 c_proj(降维),你 phi 取的是 c_proj。
OLMo-2 大概率用 gated MLP(SwiGLU 那种):有 gate_proj、up_proj、down_proj 三个
矩阵,门控相乘。这意味着:

  - 你不能直接套 "layer 9 的 c_proj" 这个名字,OLMo 没有这个模块。
  - 需要决定 phi 取哪个矩阵。建议取 down_proj(它在结构上对应 GPT-Neo 的 c_proj,
    都是 MLP 最后那个"降维回 hidden"的线性层,且都是普通线性层、EK-FAC 的
    Kronecker 近似在它上面最干净)。gate_proj 和 up_proj 涉及门控相乘的非线性,
    EK-FAC 假设会脏一些,先不碰。
  - 层的选择:GPT-Neo 取的是第 9 层(共 12 层,约 3/4 深度处)。OLMo-2-1B 层数
    不同(查实际层数),取相同相对深度的那一层(约 3/4 处),保持跟 GPT-Neo 可比。
  - 先确认 down_proj 的 shape,据此估 Fisher 子块大小和显存。

这一节的产出:明确写下 OLMo 的 phi 是"第几层的 down_proj、shape 多少、多少参数",
跟 GPT-Neo 的"第9层 c_proj、2.36M 参数"并排列出来,确认两者相对深度一致、量级可比。

==========================================================================
第 3 节:阶段一 —— SFT 快测(笼统毒性方向,探生死)
==========================================================================

theta-star = OLMo-2-1B-SFT(下载的现成 SFT 模型)。
reference policy = OLMo-2-1B 预训练版(SFT 的起点)。
beta:SFT 模型不是 KL-RL 训出来的,没有训练时的 beta。这里要明确一件事——

  重要的概念问题:SFT 模型严格说不在 KL-RL 框架里(它没有 reward、没有 KL 惩罚)。
  所以"A2:模型等于 KL-RL 最优策略"这个假设,对 SFT 模型不能原样套。处理方式:
  把 SFT 模型当成"一个偏离了预训练 reference 的策略",beta 取一个标称值(比如沿用
  GPT-Neo 的 0.2365,或扫几个值 0.1/0.2/0.5 看 ICC 对 beta 的敏感性),有效奖励里
  的 reward 仍用 RoBERTa 无毒 logit。这样测的是"SFT 模型在这个标称 beta 下,有效
  奖励在同 prompt 内的方差有多大"。
  
  这一节你先想清楚再做:如果觉得"SFT 不在 KL-RL 框架里、套 A2 没意义",停下来
  报告你的顾虑,我们讨论。我的初步看法是:SFT 快测的价值不在于"严格检验 A2",
  而在于"看一个更接近最优、监督学习训出来的策略,有效奖励方差是不是天然比 PPO
  小"——这是个有意义的对照,即使框架不完全对齐。但你要是有更好的想法,提出来。

笼统毒性方向(评估方向 g_f)的构建:
  1. 从 Lee 的 toxicity_pairwise 取 100 个(非毒性句, 毒性句)配对。
  2. 对每个毒性句,算 theta-star 在该句上的 log 概率梯度(只在 phi 子空间,
     mean reduction,prompt mask,batch=1,跟 GPT-Neo 一致)。
  3. 对每个非毒性句,同样算梯度。
  4. 基线相减:g_f = (100 个毒性句梯度的平均) 减 (100 个非毒性句梯度的平均)。
     这个差向量把"话题"消掉、只留"毒性"方向,比直接用毒性句梯度干净。
     (同时也算一个不相减的版本作对照,看两者温度计差多少。)

阶段一要测的:
  - ICC:在 OLMo-SFT 上,采一批 prompt(100 个,每个采 32 条回答),算有效奖励
    的组内相关系数,跟 GPT-Neo 的 0.89 比。
    (prompt 来源:RealToxicityPrompts,跟 GPT-Neo 一致。)
  - 温度计:用上面的笼统 g_f,算 (Delta 乘 p 的长度) 除以 (g_f 的长度)。
    Delta 的构建复用 Phase 4 的 Delta-VP(on-policy 采样、HVP double-backward)。
  - 两半余弦:报告 Delta 乘 p 的两半收敛性,跟 GPT-Neo 一样的诚实标准。

阶段一判据(探生死):
  - 活(A2 在 SFT 上成立):ICC 明显低于 0.89(比如低于 0.5),且温度计明显小于 0.3
    (比如小于 0.1)。结论:GPT-Neo 的失败是 PPO 的锅。停下报告,等我决定进阶段二。
  - 死(A2 照样崩):ICC 还是高(0.8 以上),温度计还是大(超过 0.3)。结论:A2 失效
    是普遍的、是方法的死穴。停下报告,我们讨论是写普遍性结论还是做精简 PPO 对照。
  - 中间地带:照实分层报告,我们一起看。

阶段一做完一定停,不要自动进阶段二。

==========================================================================
第 4 节:阶段二 —— OLMo PPO 去毒 + 细分评估方向(SFT 探活之后才做)
==========================================================================

只有阶段一判定"活"了,才做这一节。这一节跟 GPT-Neo 严格同范式可比。

PPO 训练:
  - 在 OLMo-2-1B 上跑 PPO 去毒,设置尽量对齐 GPT-Neo 的 Phase 0(同 reward model
    RoBERTa、同 RealToxicityPrompts、k1 KL、自适应 beta、min_new_tokens 那套防长度
    崩溃的教训照搬)。
  - 选 Pareto 最优 checkpoint 当 theta-star,记录它的 beta。
  - 注意 OLMo-2-1B 比 GPT-Neo-125M 大约 8 倍,PPO 训练显存和时间都更高,先小规模
    smoke test 跑通再全量。

细分评估方向的质控管线(C1 种族 / C2 性向 / C3 性别),四道质控一道都不能少:

  质控 1 —— 主题筛选不靠人眼,靠标注 + 互斥词表:
    - 用 RealToxicityPrompts 自带的细分维度分数(identity_attack、sexually_explicit
      等,这些是数据集里现成的 Perspective 标注,不用调 API)卡总毒性阈值。
    - identity_attack 不区分种族/性别/性向,所以叠加关键词表分主题:种族词表、
      性别词表、性向词表,三个表互斥检查——一条 prompt 命中多个主题就剔除,保证
      每条干净归一类。词表要列出来、可复现,不靠临时判断。
    - 每类筛出 100 条干净 prompt。

  质控 2 —— 生成续写后做毒性过滤,只留真高毒的:
    - 每条 prompt 用 theta-star 生成续写。
    - 用 RoBERTa 给"prompt+续写"打分,只保留确实高毒的续写(卡阈值)。低毒的、
      跑题的扔掉。这样方向里不混跑题续写的梯度。

  质控 3 —— 配同主题非毒基线相减:
    - 对每一类,另外准备一批"同主题但非毒性"的续写(比如同主题 prompt 但模型给出
      中性续写,或从非毒语料里找同主题句)。
    - 评估方向 = (该类高毒续写梯度平均) 减 (该类同主题非毒续写梯度平均)。
      这样消掉"话题"、只留"该类毒性"方向。这是细分版的基线相减,跟阶段一笼统版
      同理但分主题做。

  质控 4 —— 检测器一致性:
    - 算有效奖励 R 的检测器全程用 RoBERTa(跟 GPT-Neo 可比,不换)。
    - 主题筛选可以用 RealToxicityPrompts 自带的 Perspective 标注 + 词表;需要更细
      维度时可临时用 Detoxify 辅助筛,但 Detoxify 绝不进入 R 的计算(换检测器会
      让温度计跟 GPT-Neo 不可比)。

阶段二测的:跟 GPT-Neo 的 Phase 4 完全对应——E1(advantage 分布 + 方差分解 + ICC)、
E2(非平稳度 G 的范数 + 自然梯度步长)、E3(三个细分方向各自的温度计 + 完整修正排序
对比)。逐项跟 GPT-Neo 的数字并排。

阶段二判据:
  - 如果 OLMo-PPO 上温度计也大 → PPO 范式上 A2 普遍失效,即使换更干净的模型也救不了
    PPO,而 SFT 能成立(阶段一)说明问题在 PPO 的非最优性。一个清晰的"PPO vs SFT"
    对比结论。
  - 如果 OLMo-PPO 上温度计中等(比如 0.15 这种,不是 GPT-Neo 那种 34):
    那你那个"加 Delta 修正狠狠分析"的想法终于能用上了——这种温度计下 MINRES 能
    收敛、Delta 能测准。这时候值得真跑全阶 MINRES,算出修正后的影响力排序,做精细
    分析。这是坑活的最好结局。
